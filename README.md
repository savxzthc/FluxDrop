# FluxDrop

**Send files from your PC to your phone with one QR scan. No app, no account, no cloud.**

## What Is FluxDrop?

FluxDrop is a desktop app for sending files or folders between a Windows PC and a phone over local Wi-Fi. The PC hosts a temporary local HTTPS transfer page, the phone opens it in a normal browser, and the payload streams directly between the devices.

## Why FluxDrop?

AirDrop is excellent but Apple-centered, Bluetooth is slow for larger files, Google Drive requires an account and uploads to a cloud service, and USB cables are inconvenient. FluxDrop is intentionally narrower: choose files or a folder, scan one QR code, and transfer through the phone browser on the same network.

## Features

- Single-file PC-to-phone sharing
- Multi-file and folder sharing as an on-the-fly ZIP with bounded memory use
- Phone-to-PC Receive mode with a PC-chosen destination folder
- Local HTTPS server bound to a detected or user-selected LAN address
- Per-LAN-IP self-signed certificate generated and stored locally
- Cryptographically random one-time token with 160 bits of entropy
- Configurable 5/10/30/60-minute automatic link expiration
- Single-use or reusable-until-expiry links
- QR code generated by the Rust backend
- Self-contained mobile download page with no external assets
- Real-time desktop transfer status and progress
- Explicit PC approval before a phone can start downloading
- Manual cancellation from the desktop app
- Close-to-tray operation that keeps active transfers running
- Persisted System, Light, and Dark appearance modes with automatic Windows theme following
- Native-style Send, Receive, and Settings workspaces with responsive desktop navigation
- Persisted transfer history with outcomes, device IP, clear-history controls, and repeat actions
- Filename sanitization, HTML escaping, security headers, and invalid-token rate limiting

## What FluxDrop Does Not Do Yet

- Cloud sync, accounts, login, or relay servers
- Publicly trusted certificates or cryptographic device identity
- Remembered-device discovery or mDNS advertisement

## Privacy & Security

FluxDrop never uploads the file to a server. It serves the file from your PC to your phone over your local network and stores transfer tokens in memory only.

Transfer pages, metadata, uploads, and downloads use HTTPS with a certificate generated by FluxDrop for the selected LAN IP. The certificate and private key stay in the app configuration directory and are regenerated when the selected IP changes.

Because the certificate is self-signed, the phone shows a browser warning the first time it connects. The QR code opens a generic HTTP instruction page, with the secure URL held only in the browser fragment so the token is not sent in that HTTP request. After the user confirms the browser warning, token-bearing requests and file data are encrypted. This protects against passive Wi-Fi sniffing, but a self-signed certificate does not authenticate the PC and cannot prevent an active man-in-the-middle attack on a hostile network.

Download links use URL-safe random tokens generated from 20 random bytes. They expire after the configured 5/10/30/60-minute window and are single-use by default.

Transfer history is stored locally in the app configuration directory. It contains display metadata, the phone IP when available, and the original local source or destination paths needed for repeat actions. It never stores transfer tokens, URLs, certificates, or file contents, and it can be cleared from the History workspace.

## Requirements

- Windows 10/11 x64
- PC and phone on the same Wi-Fi network
- No phone app required
- Rust stable, Node.js LTS, and the Tauri CLI for development

## Download

Windows installers are published on the [GitHub Releases page](https://github.com/savxzthc/FluxDrop/releases). Each tagged release includes both an NSIS setup executable and an MSI package.

## Windows Firewall Note

Windows Defender Firewall may ask whether to allow FluxDrop on private networks. Allow private networks so your phone can reach the local server. Do not allow public networks unless you understand the risk.

## Troubleshooting

- Make sure the PC and phone are on the same Wi-Fi network.
- Disable VPN software temporarily if the phone cannot open the QR link.
- Avoid guest Wi-Fi networks; many isolate devices from each other.
- Confirm Windows Firewall allows FluxDrop on private networks.
- Open Settings and select the correct LAN adapter if a VPN or virtual adapter is chosen.

## Manual QA Steps

1. Start the app with `npm run tauri dev`.
2. Choose a small test file with the system picker.
3. Confirm a QR code and local URL appear.
4. Scan the QR code with a phone on the same Wi-Fi.
5. Confirm the generic connection page explains the self-signed certificate, then tap Continue securely.
6. On first connection for that LAN IP, use the browser's Advanced / Proceed action and confirm the final URL starts with `https://`.
7. Confirm the mobile page shows file name, size, type, and a waiting-for-approval message.
8. Confirm the desktop shows the phone IP and Approve / Deny actions.
9. Approve the request, then tap the enabled download action on the phone.
10. Confirm desktop status changes to Downloading and progress reaches 100 percent.
11. Confirm the downloaded file matches the source file.
12. Refresh the phone URL and confirm the link is expired.
13. Start a second share, deny it, and confirm the phone shows Transfer Denied.
14. Start a third share and leave it pending for 60 seconds; confirm the phone shows Approval Timed Out.
15. Start another share and click Cancel link.
16. Open the cancelled link and confirm the mobile page says Transfer Cancelled.
17. Select multiple files and confirm the phone receives one ZIP with every file.
18. Select a folder containing nested files and confirm the ZIP preserves the relative folder structure.
19. Switch to Receive from phone, choose a destination folder, and scan the new QR code.
20. Select a phone file and confirm the desktop approval prompt shows the exact name, size, and phone IP.
21. Approve it, confirm desktop upload progress reaches 100 percent, and verify the final file appears only after completion.
22. Repeat with a file above the configured upload limit and confirm it is rejected without a partial named file.
